# 阶段呈现模式选择规范

状态：已随不可变预发布版 `0.1.0-rc.2` 发布；应用仍须完成自身兼容性、独立验收与部署门。

## 目的

Nidec 应用中存在两种外观相近但业务含义不同的“阶段”呈现。本规范要求应用先确认业务语义，再选择组件；不得仅根据喜欢圆形还是箭头来选择。

## 选择规则

| 判断问题 | 应使用 | 原因 |
| --- | --- | --- |
| 用户点击某一项只是在同级页面、工作区或视图之间切换，不会改变业务流程状态 | `StageNavigator` | 它是可交互导航，行为接近 Tab。 |
| 当前阶段由服务端、审批结果、业务命令或状态机决定；用户只能回看已到达阶段的内容 | `BusinessProcessFlow` | 点击只是查看，不改变业务流程位置；未来阶段没有业务数据，不能点击。 |
| 点击阶段是否会改变业务状态尚未明确 | 暂不接入，记录 `Business Rule Pending` | Design System 不替应用推断业务规则。 |

最简单的判断方法：

- **只改变“用户正在看哪里”**：使用圆形编号的 `StageNavigator`。
- **同时代表“业务现在走到哪里”和“用户在看哪里”**：使用箭头形的 `BusinessProcessFlow`，分别传入权威流程状态和受控的查看位置。
- **需要推进或退回流程**：箭头点击不执行此类命令；将“提交审批”“批准”“退回”等动作放在独立且明确标注的 Button 或 Menu 中。

## `StageNavigator`：可点击的工作区导航

适用场景：

- 一个对象下面的 Definition、Parameters、BOM、Calculation 等同级工作区。
- 用户可以根据权限直接进入任意可用工作区。
- 切换只改变当前视图或路由，不自动写入新的业务生命周期状态。

应用必须负责：

- 提供唯一的阶段 `id`、名称、说明和各节点自身的状态；节点状态决定底色。
- 用独立的 `selectedStageId` 表示用户正在查看的位置。实现 `onStageSelect`，并负责路由、更新选中位置和对应页面内容；点击不得为了制造选中效果而改写节点状态。
- 决定哪些工作区禁用，以及切换前是否需要处理未保存内容。
- 保证鼠标、Enter 和 Space 最终执行相同的导航结果。
- 选中圆点的外圈只表示查看位置，不表示业务流程进度；未来工作区可以提前进入查看准备内容，其灰色底色保持不变。

连接线是工作区之间的结构关系，不是业务流程进度条。因此，`StageNavigator`的全部连接线固定使用品牌色，不随`completed`、`current`、`upcoming`或`error`状态变化；状态只控制圆形节点。连接线使用细线，并与两端圆形节点保留间隙，避免产生进度填充或穿过节点的错觉。应用不得用页面级CSS重写连接线颜色、粗细或端点位置。

```tsx
<StageNavigator
  aria-label="Configuration workspaces"
  stages={workspaceStages}
  selectedStageId={selectedStageId}
  onStageSelect={(_, stage) => setSelectedStageId(stage.id)}
/>
```

禁止：

- 用它显示审批、报价、发布等服务端生命周期，然后允许用户任意点击跳过业务规则。
- 在组件内部编码应用路由、保存、权限或 API 请求。
- 在整列外部再叠加一个更大的点击区域。

## `BusinessProcessFlow`：业务流程与受限回看

适用场景：

- Quote、Approval、Release 等由业务状态机控制的真正 BPF。
- 当前阶段由服务端结果或应用权威状态决定。
- 用户可点击已完成或当前阶段回看对应内容；尚未到达的未来阶段不渲染按钮，不能点击。
- 用户只能通过明确的业务命令推进、退回或终止流程。箭头点击绝不执行这些命令。

应用必须负责：

- 根据权威业务状态计算并传入 `completed`、`current`、`upcoming` 或 `error`。
- 负责允许的状态迁移、验证、RBAC、并发控制、持久化、API 和错误处理。
- 在组件之外提供明确的业务操作，并在成功返回后刷新阶段状态。
- 提供本地化的 `statusLabel`，让辅助技术理解每一步状态。
- 用 `viewedStageId` 单独控制正在查看的已到达阶段，并在 `onStageView` 中只更新视图或路由；不改动传入的流程 `status`。
- 箭头底色只表达流程状态；选中查看位置时沿原箭头外侧偏移绘制一圈品牌绿细线，中间留白，和 Stage Navigator 的选中外圈语义一致。箭头本体的尺寸、底色与阶段状态不因选中而改变；不使用光晕或悬停边框。
- 业务尚未到达的阶段一律标为 `upcoming`；公共组件不推断权限或是否已产生业务数据。

```tsx
<BusinessProcessFlow
  aria-label="Quote lifecycle"
  stages={serverReportedStages}
  viewedStageId={viewedStageId}
  onStageView={(_, stage) => setViewedStageId(stage.id)}
/>
```

禁止：

- 为 `upcoming` 阶段增加链接、按钮或外围点击区域。
- 在 `onStageView` 中直接把某一步标为业务当前状态。
- 将状态迁移、权限判断或失败恢复逻辑复制到共享组件包。
- 在窄屏时隐藏、重排或折行改变流程顺序；组件会在自身边界内横向滚动。

## 兼容入口与迁移

旧的 `ProcessStageIndicator` 因为同时允许“可点击”和“只读”两种解释，已经标记为弃用，仅用于保持既有代码暂时可编译。新代码不得使用它。

迁移时必须先回答上述判断问题：

1. 如果它是同级导航，迁移为 `StageNavigator` 并保留应用导航合同。
2. 如果它是真正的生命周期，迁移为 `BusinessProcessFlow`。已到达阶段可提供回看入口，业务动作仍放在应用拥有的 Button 或 Menu。
3. 如果语义不确定，停止迁移并由对应应用确认业务规则。

共享包只统一呈现和基础交互质量；阶段名称、流程定义、业务动作和应用验收始终由消费应用负责。
