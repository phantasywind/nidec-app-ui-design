# `@phantasywind/nidec-app-ui-design@0.2.0`

Status: RELEASED (2026-10-13). GitHub Release: [v0.2.0](https://github.com/phantasywind/nidec-app-ui-design/releases/tag/v0.2.0). GitHub Packages channel: `latest` (consumers must still pin `0.2.0`).

Prepared and released by Claude as maintainer (ADR-0007). Accountable owner and authorizer: Locke Yuan. Source commit `c44ca4775a591e2af479e626c1a269d6b4fec5a7`; immutable tag `v0.2.0` points at it and was pushed only after publication succeeded.

## Change type

Minor release relative to `0.1.2`. New exports and new props on existing components, plus visual changes. No export was removed, and the exact Fluent, React and date-picker versions applications install are unchanged. No business behaviour is included.

Comparing the built entries of `0.1.2` and this source: no export name was removed from `index`, `layouts` or `date-picker`; the additions are listed below.

### New exports

| Entry | Export | Purpose |
| --- | --- | --- |
| root | `MultiSelectDropdown` | Several values from a fixed list; tags in the trigger or, with `tagPlacement="below"`, a short trigger with removable wrapping tags and Clear all; optional `searchable`. |
| root | `SingleSelectDropdown` | One value from a fixed list: a Dropdown below 12 options, a filtering Combobox at 12 and above. |
| root | `LiteEditableGrid` | Lightweight virtualised editable grid: plain-text cells, one mounted editor (`text`, `longText`, `select`, `combobox`, `multiselect`, `none`), full keyboard model, optional one- or two-level collapsible groups. |
| root | `BusinessProcessStageDetail` | Content of the stage detail card opened by `BusinessProcessFlow` `renderStageDetail`. |
| root | `Pagination`, `FactList`, `FormDrawer`, `SectionNavigation`, `StepStatusIcon`, `TableScrollRegion`, `WorkspaceStack` | Building blocks requested in consumer feedback on `0.1.2`. |
| `/date-picker` | `BusinessDatePicker`, `businessDateToDate`, `dateToBusinessDate`, `formatBusinessDate`, `parseBusinessDate` | Calendar dates as `yyyy-MM-dd` strings, shown as `22 Oct 2026`, never passing through UTC. |

### Changes to existing components

| Component | Change | Who is affected |
| --- | --- | --- |
| `NidecProvider` | Fluent portals (Dialog, Drawer, Menu, Popover, Tooltip) mount in a body-level host carrying the package scope, so package styles reach portal content. | Every application. Applications that marked `body` with the scope attribute as a workaround can remove it. |
| `BusinessProcessFlow` | Flat arrows without the viewed-stage outline: reached stages deep green, the viewed stage brand green, upcoming grey, error red. New `renderStageDetail`. Stage names wrap to two lines with equal arrow heights. New `revisit` stage status (hatched, viewable). | Applications using the flow. Code that switches exhaustively over the stage status type must handle `revisit`. |
| `ApplicationNavigation` | `footer` slot; `ApplicationNavigationItem` `badge`; the navigation is one viewport tall and sticky. | Applications using the application frame. Check page layouts that relied on the navigation scrolling with the page. |
| `ApplicationTopBar` | Optional `breadcrumb` row. | Opt-in. |
| `PageHeader`, `WorkspaceSection` | `title` accepts any React node (it previously collided with the HTML `title` attribute); `PageHeader` gains `titleAdornment`. | Opt-in; existing string titles are unchanged. |
| `SegmentedControl` | Accepts `value={null}`. | Opt-in. |
| `DirectoryWorkspace` | `resultsTitle` and `resultsActions` wrap toolbar, results and pagination in one module. | Opt-in; the default is unchanged. |
| `Option` (Dropdown, Combobox) | Unselected hover is the neutral grey `colorNeutralBackground1Hover` instead of light green; checked multiselect options get the light-green selected fill. | Applications using Dropdown or Combobox. |
| Directory results, versioned content | No stray vertical scrollbar beside a horizontal one. | Visual only. |
| `RecordIdentityCellLayout` | The page selection guide deprecates `secondary` under the new one-field-per-column rule. The prop still works and its type is unchanged. | Plan to move the secondary value into its own column. |

## What applications should do

- Update the exact pin to `0.2.0`. Dependencies are unchanged: `@fluentui/react-components@9.74.7`, `@fluentui/react-datepicker-compat@0.6.39` (only for `/date-picker`), and an exact React / React DOM 19.2.x pair.
- Re-inspect Business Process Flows, application navigation, Dropdown and Combobox popups, and any Dialog, Drawer, Menu, Popover or Tooltip that relied on a local styling workaround.
- Remove local workarounds the release makes unnecessary (scope attribute on `body`, local stage-detail popovers, local pagination or fact lists) only after checking the result.
- New components are optional; nothing has to be adopted to upgrade.

## Adoption after publication

Configure `@phantasywind:registry=https://npm.pkg.github.com` without storing credentials in the repository, then install:

```powershell
npm install --save-exact @phantasywind/nidec-app-ui-design@0.2.0 @fluentui/react-components@9.74.7
# Only when consuming /date-picker:
npm install --save-exact @fluentui/react-datepicker-compat@0.6.39
```

Read the version-matched [adoption guide](../consumer-ui-adoption.md) and [component catalog](../component-catalog.md) at the `v0.2.0` tag. The archive includes dist and README only.

Consumers keep their previous exact package and lockfile (`0.1.2`) as the rollback point and own application testing, acceptance and deployment. Publication of this version is not application adoption approval, independent acceptance or Production approval.

## Unchanged and out of scope

- The table-header colour direction (`docs/table-header-visual-direction.md`) is still not implemented.
- Documentation, the Claude Design System build under `design-system/` and the release workflow are repository changes only and are not part of the package.
