# `@phantasywind/nidec-app-ui-design@0.3.0`

Status: PREPARED, not yet published. Qualification and publication evidence below is Pending until the release workflow runs.

Prepared by Claude as maintainer (ADR-0007). Accountable owner and authorizer: Locke Yuan. It carries the second-round consumer feedback (#19), the two lightweight editable grids (#20) and the three button types (#21).

## Change type

Minor release relative to `0.2.0` under the pre-1.0 rule. New exports and new props, visual fixes, and two breaking changes that applications must handle before updating (next section). The exact Fluent, React and date-picker versions applications install are unchanged.

Comparing the built entries of `0.2.0` and this source: `index` removes `ToggleButton`, `MenuButton`, `SplitButton` and their props types and adds the exports listed below; `layouts` is unchanged; `/date-picker` adds only the types `BusinessDateInvalidReason` and `BusinessDateInvalidInput`.

## Breaking changes

| Change | Effect when updating | What applications do |
| --- | --- | --- |
| `LiteEditableGrid` `rowHeight` defaults to `auto` (was 32). | No compile error. A grid without `rowHeight` now wraps text and renders every row instead of virtualising, which slows grids beyond a few hundred rows. | Pass `rowHeight={32}` (or 40/48) to every large LiteEditableGrid before updating. |
| `Button` `appearance` accepts only `primary`, `attention` and `secondary`; `IconButton` only `primary` and `secondary`. `ToggleButton`, `MenuButton` and `SplitButton` are no longer exported. | **Compile error** for `appearance="outline"`, `"subtle"` or `"transparent"`, and for imports of the removed buttons. | Replace them as described under Button types below. |

## Fixes

| Component | Change | Application workaround this lets you remove |
| --- | --- | --- |
| Dropdown, Combobox, `SingleSelectDropdown`, `MultiSelectDropdown` | Opening the popup no longer scrolls the page when `html` or `body` is 100% tall. | Local `scrollIntoView` patches or removing `height: 100%`. |
| Same | The control shrinks to its field (`--nidec-ui-select-width`, default 250px, 100% inside `FormGrid`) and the selected text ends in an ellipsis; the arrow stays visible. | Local `min-width: 0` / width overrides on the Fluent root and button. |
| `BusinessProcessFlow` | Stage names break only between words; narrow stages hide the marker so names stay whole. | Local `word-break` or font-size overrides. |
| `Badge` | No wrapping inside the package scope. | Local `white-space: nowrap`. |
| `BusinessDatePicker` | Typed text that cannot be read or is outside min/max sets `aria-invalid` and calls `onInvalidInput` with the text, reason and parsed date. | Local parsing wrappers to detect rejected input. |

## Button types

Locke decided on 2026-10-26 that there are three button types: primary, attention and secondary.

| Change | What applications do |
| --- | --- |
| `Button` `appearance` takes `primary`, `attention` (new: amber `#e08a00` with white text, a new 17th palette role `attention` in `tokens.css` / `tokens.json`) or `secondary` (default). `outline`, `subtle` and `transparent` no longer compile. | Replace them with `secondary`, or `attention` for starting a change or sending back. |
| `IconButton` `appearance` takes `primary` or `secondary`. | Replace `subtle` / `transparent` with the default. Row actions keep `TableActionIconButton`. |
| `ToggleButton`, `MenuButton`, `SplitButton` (and their props types) are no longer exported. | Use `MoreActionsMenu` for a menu, a Button for a command, `SegmentedControl` for a choice. |
| `MultiSelectDropdown` "Clear all" is a small secondary button instead of a transparent text button. | Nothing. |

## Editable grids (decided 2026-10-26)

Locke decided on 2026-10-26 that every editable table uses one of two lightweight grids: LiteEditableGrid (cell edit, preferred, for BOM templates and project BOMs) or the new LiteRowEditGrid (row edit, for long uniform data such as component master and cost management). A Fluent Table with Fluent inputs inside `EditableGrid` still works but is no longer recommended.

| Export or prop | Change | Replaces in applications |
| --- | --- | --- |
| New `LiteRowEditGrid` (`onRowChange`, `rowHeight` 32/40/48, `height`, `maxHeight`, `canEditRow`, `onActiveRowChange`) | Row edit: Enter, F2 or a double-click edits the current row; leaving the row or Enter saves it with one `onRowChange`, Esc discards. No actions column. Fixed rows with virtual scrolling for thousands of rows; no groups. The editing row is light green with regular-weight values and an underline on the focused field, without per-cell boxes. | Table rows with Fluent `Input` / `Dropdown` in the active row and their confirm and cancel actions, local row-height and control-size overrides. |
| `LiteEditableGrid` `rowHeight` default **`auto`** (was 32), also 32/40/48; `onActiveRowChange` | **Behaviour change:** without a `rowHeight`, rows now wrap their text and every row is rendered (about 300 rows). **Grids with thousands of rows must pass a fixed `rowHeight`** to keep virtual scrolling. The editor is a white field without a frame, and the edited row turns light green. | Local row-height overrides. |
| Column `editor: 'number'` | Decimal keyboard, end-aligned. | `text` columns with local alignment. |
| New `formatCurrency(amount, currency, { display, decimals })`; column `format(value, row)` in both lightweight grids | Currency rule (Locke, 2026-10-26): symbol before the number with one space, thousands separators, fixed decimals (`$ 100.00`); symbols for USD and CNY only, ISO code for every other currency (`JPY 1,200`). `format` changes only the resting cell text. | Local currency formatting and amounts without a symbol. |
| `EditableGrid` `title` and `toolbar` optional, `density="compact"`, `maxHeight` | No empty header or toolbar strip; compact frame; sticky header under a capped height that can follow the window. | Empty-title workarounds, CSS hiding the empty toolbar, local sticky-header CSS. |
| `EditableGrid` action column | Only the header cell marked `nidec-ui-editable-grid__action-column` is pinned, no longer whatever header is last. **Applications using a Table must add the class to their Actions `TableHeaderCell`.** The editing-row action cell colour is limited to EditableGrid. | Local overrides that un-pinned the last column. |

A date editor inside the grid comes in a later round.

## What applications should do

- Before updating, pass `rowHeight={32}` to any existing LiteEditableGrid with more than a few hundred rows, and replace `outline`, `subtle` and `transparent` button appearances and the removed button exports.
- Update the exact pin to `0.3.0`. Dependencies are unchanged: `@fluentui/react-components@9.74.7`, `@fluentui/react-datepicker-compat@0.6.39` (only for `/date-picker`), and an exact React / React DOM 19.2.x pair.
- Move editable tables to LiteEditableGrid (BOM-type lines) or LiteRowEditGrid (long uniform data) one at a time, and add `nidec-ui-editable-grid__action-column` to the Actions header of any Table kept inside `EditableGrid`.
- Re-inspect Dropdown and Combobox width in forms and toolbars, Business Process Flows at 900px, and tables that use local sticky CSS.
- Remove the local workarounds listed above one at a time, checking the result each time.

## Adoption after publication

Configure `@phantasywind:registry=https://npm.pkg.github.com` without storing credentials in the repository, then install:

```powershell
npm install --save-exact @phantasywind/nidec-app-ui-design@0.3.0 @fluentui/react-components@9.74.7
# Only when consuming /date-picker:
npm install --save-exact @fluentui/react-datepicker-compat@0.6.39
```

Read the version-matched [adoption guide](../consumer-ui-adoption.md) and [component catalog](../component-catalog.md) at the `v0.3.0` tag. The archive includes dist and README only.

Consumers keep their previous exact package and lockfile (`0.2.0`) as the rollback point and own application testing, acceptance and deployment. Publication of this version is not application adoption approval, independent acceptance or Production approval.

## Unchanged and out of scope

- A date editor inside the lightweight grids and print-document components come in a later round.
- The table-header colour direction (`docs/table-header-visual-direction.md`) is still not implemented.
- Documentation, the Claude Design System build under `design-system/` and the release workflow are repository changes only and are not part of the package.
