## Released scope

This release retains the governed element and composite contracts from `0.1.0-rc.2` and adds the first qualified shared page-layout boundary under `@phantasywind/nidec-app-ui-design/layouts`.

`ApplicationFrame`, `ApplicationTopBar`, `ApplicationNavigation`, `AuthenticationLayout`, `DirectoryWorkspace`, and `VersionedWorkspaceLayout` provide business-neutral structure for common application shells and page archetypes. The matching guidance covers Authentication, Directory / Work Queue, Record Workspace, Master Data / Form + List, and Versioned Governance pages. Applications continue to own routing, authorization, data state, API contracts, lifecycle rules, and business actions.

The package also adds whole-card actionable gallery entries, governed list/card view selection, page-level recipes, and the finalized interaction distinctions among record-identity links, same-surface row selection, compact row actions, clickable `StageNavigator`, and read-only `BusinessProcessFlow`. It includes the governed `InlineModeTabs` local-editor pattern without conflating it with page tabs or segmented page-mode selection.

No CPQ route, DTO, role, business status machine, API, field schema, Dark Mode, custom font, chart system, or deployment behavior is included.

## Known limits

The browser seal retains `axe-color-contrast-incomplete:process-stage-overlap` for pseudo-element overlap analysis. Independent computed-color and connector-geometry assertions passed. The retained `style-src-elem:inline:line-135` CSP report is disclosed as an environment signature and is not treated as proof of deployed-host CSP compatibility.

Some broad demonstration consumers produce Vite's warning for JavaScript chunks above 500 kB. The warning remains an application code-splitting observation; no artificial threshold was raised and the shared package does not define a universal application bundle budget.

Package qualification does not establish independent application acceptance, deployment authorization, Production approval, all-browser WCAG compliance, deployed-host CSP compatibility or business-process correctness. Applications consume only this exact version, preserve their own lockfile and business contracts, and complete their own compatibility, acceptance, deployment and rollback gates. Corrections require a new version and tag; `0.1.0-rc.3` must never be overwritten or reused.
