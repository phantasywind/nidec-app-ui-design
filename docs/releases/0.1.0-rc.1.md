## Frozen first-release scope

The release candidate provides framework-neutral light-theme tokens and static composite styles plus a finite React API for forms, overlays, feedback, navigation, menus, tables/data grids, cards, content/status controls and three business-neutral compositions: `CollectionList`, `CardGallery`, and `ProcessStageIndicator`.

Data Table presentation uses the approved Fluent Table family directly; sorting, selection, pagination, virtualization, loading, column meaning and business status mapping remain consumer-owned. Process stage transition rules, permissions, persistence and routing also remain consumer-owned.

The later `RecordIdentityCellLayout` mainline contract is not part of this immutable release. Consumers remaining on this RC may use Fluent `TableCellLayout appearance="primary"` and its `description` slot directly, without application font CSS, while retaining application ownership of which field is the record identity.

No application DTO, API, RBAC rule, route, business state machine, Dark Mode, custom font, icon registry, chart system or file-upload workflow is included.

## Release hardening deltas

- Replace publication-blocked scaffold tokens with 16 ADR-0006 light-theme roles generated into `tokens.css`, `tokens.json`, and the internal Fluent theme palette.
- Keep both static CSS entrypoints explicitly side-effectful while React, React DOM and Fluent remain external peers.
- Reduce the interactive process-stage target to its content and terminate connectors at marker edges; use Fluent transparent-button states so hover paint does not cover the connector.
- Guard actual publication behind exact explicit authorization, a clean worktree and matching immutable tag.
- Add a cold Navigation install/build check for the reported EIDC `@fluentui/react-icons` question. Fluent 9.74.7 currently resolves icons transitively; the shared package will not invent a direct dependency unless isolation reproduces a missing runtime contract.

## Known limits

Package qualification does not establish application acceptance, Production approval, all-browser WCAG compliance, real deployment CSP compatibility or business-BPF correctness. Any retained browser/tool sentinel must be stated in the final evidence rather than waived.

At the 720px bounded horizontal Data Table viewport, axe can return `color-contrast` as incomplete for the clipped Fluent `Actions` header with `elmPartiallyObscured`; it does not report a contrast violation. The release seal permits only this exact viewport, scrollable-region, Fluent-header and message-key signature, records it as `axe-color-contrast-incomplete:scrollable-table-clipping-at-720`, and continues to reject all other unrecognized targets.

The process-stage geometry check also retains the bounded `axe-color-contrast-incomplete:process-stage-overlap` scanner signal. The independent geometry assertions verify that connector endpoints do not overlap the marker border box and that hover paint does not cover the connector; the retained scanner signal is disclosed rather than generalized into an accessibility pass.

This release is an immutable release candidate for controlled adoption. It is not the future stable `0.1.0`, independent acceptance by CPQ/EPM/EIDC, deployment approval or Production approval. Any correction requires a new version and tag; `0.1.0-rc.1` must not be overwritten or reused.
