# 下一任务包候选：完整表单区域的 Fluent 替换

状态：Locke已批准共享库按复盘下一步实施，见 `fluent-complete-region-record.md`；应用接入仍须共享验证汇报后批准。本提案不向02自动下发开工指令。

## 为什么扩大为完整区域

上一包只替换输入与选择控件，标签/错误、按钮、Sheet和提示仍由旧组件负责。下一包建议围绕完整操作区域推进，而非单纯增加散落控件数量。让用户能看到区域内由同一Fluent体系负责，同时保持业务合同。

## 建议覆盖与排除

| 区域 | 候选完整替换内容 | 不变合同 |
| --- | --- | --- |
| Platform Builder Edit Identity/New Draft | 字段标签/说明/错误、输入选择、Clone/Blank、区域动作按钮、右侧Sheet容器 | 默认Clone/首版限制、禁用、payload、打开关闭与焦点 |
| Platform Definition编辑区域 | 字段容器与验证反馈、选择/复选、Edit/Save/Cancel动作与局部表单布局 | historical只读、required、两列信息结构、保存权限 |
| Field Governance筛选与确认区域 | 筛选表单、开关、确认弹层、说明/错误与确认取消按钮 | 开关仅开启确认、不直接保存、确认前值不变 |
| Commercial Add-on编辑Sheet | 标签与错误、输入选择、动作按钮、右侧Sheet、局部反馈 | initial focus、editing disabled、allowedActions、payload、409草稿与重试 |

这比上一包增加了字段、动作、反馈、弹层和区域布局的责任范围，但仍围绕四个已掌握的场景；不盲目同时增加陌生业务页面。其他同类页面的批量推广可在该完整区域方案验证后另列文件清单，不以本提案自动授权。

排除全局Shell、表格/树表、整个Gallery重写、全站控件barrel切换、API/RBAC/状态规则与Dark Mode。右侧Sheet仍是右侧Sheet，不因Fluent替换强改为居中Dialog；确认弹层仍按原确认流程。

## 共享能力的前置工作

当前已交付Field、Dialog及输入选择族可作为基础，但并不证明具备全部替换合同：

- Button当前仅文字children和原生属性合同；主次/危险/加载/图标动作需要先核对实际需求，再决定最小API扩展，不直接透传整库。
- Field需核对现有id、label、说明/错误关联及required展示；必填规则不进入共享包。
- 右侧Sheet需要核验固定Fluent9.74.7正式能力的受控开关、portal、焦点隔离/返回、滚动和窄屏行为；当前共享没有该合同，不以已有Dialog代替证明。
- 提示/错误/容器和布局需区分上游现成功能、必要共享组合、应用业务说明；不复制CPQ专属状态组件。

上述是待核验的需求清单，不是上游接口已通过或共享实现已获批准。先冻结本批API/类型与排除项，再一次性实施共享能力、打包验证、汇报，由Locke确认后交02应用实施。

## “全面替代”的检验方法

### 已批准的字体与尺寸原则

Locke于2026-09-06批准：迁移元素直接采用Fluent字体栈、字号/字重/行高层级以及各组件支持的尺寸档位，集中决定使用角色，不重新发明一套或叠加旧DS规则。“与旧视觉连续”不再解释为强制恢复旧像素高度和字重。

具体应用档位尚未冻结；不将原则批准写成某个字号或small/medium已批准。实施方案须统一列出正文、标签、辅助/错误、区域标题的文字角色及按钮/输入/选择的尺寸选择，核验固定9.74.7实际接口后落地。多行内容高度、响应式宽度和页面布局另列适配用途，不能把字体行高与控件高度混为一谈。

检查宿主规则是否仍控制font-family/font-size/font-weight/line-height/min-height/padding；必要例外记录原因、范围和验证，不逐页散写数值，也不借此重写全局字体。该原则不等于当前CPQ已完成统一治理，不改变本提案待批准状态。

每个批准区域建立旧/新组件所有权清单：已迁移元素的装饰、状态与焦点由Fluent负责，旧类名/背景图/伪元素不得继续控制该元素。旧业务组合名称可以保留为过渡API，但底层视觉实现必须明确迁移，不用换个外层Provider冒充完成。

保留真实宿主CSS，分别展示旧区、新区以及未迁移对照；比较默认/hover/focus/错误/禁用/只读和实际四视口。箭头、图标、边框、内外层padding、宽高、伪元素应有computed证据与可见截图。对按钮验证默认不提交与显式提交，对Sheet/确认层验证焦点、背景隔离、Escape和返回；不登录或写入真实业务数据。

工程层保留精确制品/依赖、正常类型与原样build命令、集中回归、资源增量和失败历史。旧实现仅在活动引用检查及验收后按明确清单退役，不整仓删除或全局reset。
