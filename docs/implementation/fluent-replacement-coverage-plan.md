## 不能误计为完成的能力

- 公共Button当前只接受文字children且默认type=button；不能将IconButton/链接/所有外观变体记成已覆盖。
- Field和Dialog已经导出，不等于CPQ FormField/Sheet或确认流程已迁移验收。
- Input并不自动覆盖NumberInput的数值转换、空值、精度或SearchField组合语义；这些必须按现有合同对照。
- RadioGroup/Radio/Switch虽在共享包可用，但不是旧目录每个组合的无差异替代。当前02批次的结果尚待回传。
- “共享可用”与“CPQ已替换”分开登记；“已替换”还须区分实施自测与独立验收。

## 较大下一包的组织建议（未批准）

当前四处表单批次通过后，建议按“剩余表单与目录工具区”组织一个较大批次，而不是逐控件提交：

1. 优先复用现有已验证 Input/Select/Textarea/Checkbox/Radio/Switch 能力，将本批适配经验推广到经过引用核查的其他同类位置；具体页面数量/文件由02结果和占用情况确定，现不虚构覆盖数。
2. 在共享库先确认缺项：图标动作/链接语义、Tooltip、Tab/分段导航、Combobox等是否为该场景必要；必要项需核验固定Fluent版本正式API后定义最小公共合同、整批实现与制品验证。这里仅列需求，不声称上游接口已经核验或授权实现。
3. 以场景整批交接，并配迁移前后元素对照、实际引用清单和回退清单；不采用一个组件一个安装审批循环。

表格/树表、全局Shell、Sheet全局替换和整个模板体系不与此候选包强行捆绑；它们仍进入总体替换覆盖计划，但需要各自明确交互合同。Dark Mode不进入计划。

## 每项的迁移与退役判据

### 已迁移控件不得混搭旧皮肤

Locke再次明确“全面替代不是叠加”。2026-09-06实看5188 Field governance：Fluent Select有自身SVG箭头，同时内部select的computed background-image仍为旧全局CSS的两个渐变箭头，appearance已为none。这是宿主样式泄漏，不是原生箭头，也不是允许的视觉连续性。已交02修复并检查本批同类控件；未取得修复证据前，本批视觉问题保持开放。

每个下一批任务包必须包含以下验收栏，不只列“使用了Fluent组件”：

| 检查 | 必须留存的事实 |
| --- | --- |
| 实现归属 | 实际使用共享Fluent组件；未仅给旧控件换主题色 |
| 装饰归属 | 图标/背景图/伪元素只由目标实现负责；排除旧select箭头等实际命中规则 |
| 状态归属 | 默认、hover、focus、disabled、readonly（适用时）不被旧规则覆写；不能取消焦点提示换取外观 |
| 几何归属 | 内外层padding、边框、高度与图标占位无重复累加；必要定制有局部范围和目的 |
| 宿主真实性 | 保留实际全局CSS加载顺序做浏览器核验，不卸载旧CSS制造通过；未迁移对照保持不变 |
| 回归与负向 | 为已发现旧装饰重叠补断言，并核对可见箭头唯一；DOM里只有一个SVG不够证明无背景图重叠 |

优先通过支持的Fluent主题/接口定制及局部边界排除宿主干扰，不重画旧图标、不隐藏Fluent图标掩盖、不采用破坏语义的粗暴全重置。若确需改变全局选择器或共享API，先明确影响范围并取得相应批准。该原则不等同于要求所有浏览器计算样式完全等同官方默认值，也不禁止合理布局适配。

后续登记字段：旧元素/实际使用位置、目标共享能力、应用适配、保留合同、可见差异、绑定版本/制品、测试证据、剩余旧引用、退役状态。

状态顺序：已盘点 → 目标合同已核验 → 共享制品已验证 → 应用已替换并自测 → 独立验收 → 旧实现可退役。没有证据不得跳级，也不按目录总数计算虚假迁移百分比。

旧实现退役必须先检查活动引用、测试/样例和动态入口；完成等价替代并得到相应批准后才删除旧组件及其专属CSS。临时适配层用于过渡，不长期维护两套竞争视觉实现；业务组合可继续由应用拥有，但其视觉底座向新Fluent体系迁移。不得把整个CPQ业务组件复制进共享库来伪造覆盖。
