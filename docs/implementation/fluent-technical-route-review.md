# Fluent 技术路线评审

- 日期：2026-09-04
- 状态：评审完成，建议有条件通过；待 Locke 确认技术路线门。
- 范围：设计系统仓库的技术底座选择，不是发布、CPQ/EPM 接入或 Production 批准。
- 已批准的限制处置：见 [ADR-0004](../decisions/0004-fluent-known-limitations.md)。不要求重新批准同一限制。

## 结论

建议继续采用 **Fluent UI v9 基础组件 + Nidec 主题接入、薄封装和使用治理 + 应用业务语义** 的路线，不恢复自研通用基础组件，也不复制或维护一套 Fluent 分叉。

现有证据足以支持这个有限的技术底座决定：真实包边界、Node 24 构建、Node 22 消费者、按钮/表单/对话框交互以及主题与 CSP 机制已获得具体版本的验证证据。已发现的焦点辅助节点告警和上游声明检查问题，按 ADR-0004 作为已接受限制处理，不再单独阻断本路线评审。

这不表示所有测试都是绿色，也不表示该原型已经可发布。官方浅/深主题仍是演示输入，当前 token 仍是 scaffold fixture，应用真实环境和独立验收尚未完成。

## 不需要继续重复的工作

- 不再仅为清除已接受的 sentinel 告警反复检查或改写上游节点。
- 不为额外上游声明诊断更换依赖、降级工具链或降低现有应用类型检查。
- 不重新自研已由 Fluent 提供的通用 Button/Input/Dialog。

实际焦点卡住、错误提交、禁用失效、数据状态错误、正常构建失败等仍是功能或兼容性问题，不在上述限制接受范围内。出现时重新阻断并定位。

## 请求确认的下一道门

建议确认：**接受 Fluent 9.74.7 作为当前共享 UI 技术底座，在 ADR-0004 限制下结束本轮技术路线评审，下一步仅制定 CPQ 小范围接入计划。**

接入计划应列明候选最小页面/交互、精确依赖与制品、主题/CSP 安装边界、原页面行为对照、误操作防护验收点和可回退路径。此处只是下一步内容要求，并未选择或修改 CPQ 页面。必要的 CPQ 定位材料可由其工作流提供。

批准这项技术路线结论不等于批准发布包、推送代码、修改 CPQ/EPM 或进入 Production。总体门状态在用户确认前仍为“评审完成，待确认”，不得自行记为已批准。
